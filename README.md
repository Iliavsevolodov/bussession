# Business Session — администрирование события

Мини-сервис для управления участниками Business Session и корпоратива, двумя отдельными счетами, расходами, регистрацией на входе и розыгрышами.

## Страницы

- `index.html` — закрытая админка: участники, списки БС/корпоратива, балансы, расходы, история операций.
- `checkin.html` — отдельная делегируемая страница входа: поиск, отметка «в зале», статистика присутствия и рандомайзер.

## Тарифы

- Business Session: 1 000 ₽ за участника.
- Корпоратив: 3 000 ₽.
- Корпоратив с ночёвкой 💤: 3 500 ₽.

Суммы фиксируются в журнале операций на момент регистрации.

## Финансы

Баланс не хранится одной изменяемой цифрой. Он рассчитывается из `ledger`, поэтому сохраняется история всех поступлений, расходов и сторнирований. При расходе сначала используется выбранный счёт. Если денег не хватает, остаток автоматически списывается со второго счёта. Если общей суммы недостаточно, расход отклоняется.

## База

SQL-схема: `supabase/schema.sql`.

После создания отдельного Supabase-проекта:

1. Применить `supabase/schema.sql`.
2. Установить bcrypt-хэши паролей:

```sql
update public.access_settings
set admin_password_hash = extensions.crypt('greenway', extensions.gen_salt('bf')),
    checkin_password_hash = extensions.crypt('ENTRY_PASSWORD', extensions.gen_salt('bf')),
    updated_at = now()
where id = 1;
```

3. Записать Project URL и publishable/anon key в `config.js`.

Пароли и service-role ключи не должны попадать в GitHub.

## Доступы

Админский и входной доступ разделены на уровне RPC-функций. Страница входа не получает функций для финансов, расходов или изменения состава списков.

## Публикация

GitHub Actions проверяет синтаксис JavaScript и публикует сайт в GitHub Pages после push в `main`.
